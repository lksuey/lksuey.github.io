The right customer key changes the result

A customer can have several proposals with different timestamps and statuses. Treating every row as a current case mixes historical attempts with the latest situation.

The current implementation groups records by Customer ID. This avoids merging unrelated customers when their Brazilian tax identifiers are masked. The most recent proposal is selected by date and time, with source-record order used when a timestamp cannot be parsed.

Outputs that can be checked

Unsigned, Canceled, and General modes have dedicated routines. Reports combine summaries and detailed worksheets, with cancellation analysis by reason and value.

Available worksheets depend on the selected mode and the data. The synthetic example demonstrates classification and aggregation, not production volumes or financial outcomes.

A repeatable reporting workflow

The application accepts CSV, XLSX, and XLSM files, detects CSV delimiters, checks required columns, and normalizes text, statuses, dates, and monetary values. Records outside the configured intermediary scope are filtered out.

The desktop workflow offers file selection, three processing modes, progress updates, completion messages, and error handling. Processing runs in a separate thread. Excel output includes headers, filters, totals, and mode-specific analysis sheets. The project includes PyInstaller packaging and an existing Windows executable.
